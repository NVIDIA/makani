# Changelog

## 0.4.0rc1

**Breaking**
- Layers declare the parameters not to be weight decayed through `no_weight_decay()`, by names relative to the layer, and the optimizer honours the declarations in both weight-decay modes (`makani.driver.helpers.get_no_weight_decay_parameters`). Before, the `no_weight_decay()` of SFNO and the AFNOs was never called: with weight decay, the position embeddings were decayed in `"full"` mode and, unless 1-D, in `"transformer"` mode. They are not decayed now in either mode: those of SFNO (`"direct"` and `"frequency"`), AFNO, AFNO v2, ViT and FCN3.1 (`LearnablePositionEmbedding`), and Pangu's earth position bias. A run with weight decay trains these parameters differently than before, and its optimizer state from before does not load, as it has other parameter groups; without weight decay, the declarations are left out of the groups, which are then those of earlier versions, so that such runs resume. A layer without a declaration leaves its parameters to the mode, and a declared name that is not a parameter of the layer raises; AFNO's `cls_token`, which no network has, is dropped. The driver logs the parameters that are not decayed.
- The spherical models convolve with the spectral convolution of torch-harmonics: FCN3, FCN3.1, SNO and the linear filter of SFNO build `SpectralConvS2` / `DistributedSpectralConvS2` through `makani.models.common.spectral_conv_s2`, with the truncation of their transforms. Its bias is the spectral bias of torch-harmonics, a coefficient per input channel and mode scaled by the integral of the channel, where makani added a bias per channel in grid space. The weight keeps its name and layout, and without a bias the layer computes the same, so checkpoints of these models without a bias in the spectral convolution, which no shipped config enables, load and give the same results; with one, `bias` is gone and `spectral_bias` is new. The linear SFNO filter on the sphere takes `operator_type: "dhconv"` only, and `separable: True` raises. `SpectralConv` is now the planar convolution of FNO only, with one weight per mode (`"diagonal"`, FNO's default); it initializes the weights per row of modes, where its init failed for `lmax != mmax`, and under spatial parallelism takes the local modes from the distributed FFTs, where it built weights of the global size.
- makani runs on torch-harmonics 1.0 (main at c2db977 until 1.0 is tagged; `torch-harmonics>=0.9.4.dev50,!=0.9.4`), which needs PyTorch >= 2.9. Its layers take grid descriptors instead of `(nlat, nlon, grid)`; makani builds them with `makani.utils.grids.sht_grid(img_shape, grid_type)`, and configs and makani's own layer signatures are unchanged. SFNO, FCN3 and SNO clamp the order truncation `mmax` to `lmax`, which torch-harmonics 1.0 requires: the orders `m >= lmax` they used to keep (`mmax = lmax + 1` on a grid with `nlon = 2 * nlat`) carry no spherical harmonic and were always zero. Two parameters of SFNO shrink by those orders, so checkpoints that have them do not load: the weights of the `diagonal` operator, and the `"frequency"` position embedding (`pos_embed.0` and `pos_embed.1`, 90 orders instead of 91 on 721 x 1440 with `scale_factor: 8`), whose entries at `m >= lmax` were masked out. The distributed SHTs now differ from the serial ones by a few float32 ULP. makani passes `theta_cutoff` to every DISCO convolution, so the new torch-harmonics defaults there do not apply. ICON data is still remapped onto a lat/lon grid by makani (`makani.utils.remap`); torch-harmonics does not support unstructured grids yet.
- Starting a run: a resume, when the run directory holds a checkpoint of the run, restores everything, the weights, the loss, the optimizer, the scheduler, the counters, the data pipeline and the noise generators, in the mode the run saves in (`save_checkpoint`), whatever the warm-start settings say. Before, it applied the `load_*` flags too, so a finetune config reset its counters, optimizer and schedule on every resume, and it read in `load_checkpoint` mode. A warm start from `pretrained_checkpoint_path` now takes over the weights only by default; `load_optimizer`, `load_scheduler`, `load_counters` and `load_loss` opt into the other states. The four trainers share this logic in `Driver.restore_run_state`, and the training scripts set up the run directory and detect a resume with `setup_training_run` (the ensemble script still decided by `load_checkpoint`). The scripts copy their command line options into the parameters with `arguments_to_params`, so the autoencoder script now honours `--enable_s3` and `--multistep_checkpoint`; an unknown `save_checkpoint` mode raises. A run resumes only from its own directory, so a relaunch has to pass the same `--run_num`.
- The noise of a model is driven through `model.noise`, a `NoiseController` that advances, snapshots, restores and re-seeds it; the model package exposes it as `ModelWrapper.noise`. `Rollout(batch, noise=model.noise)` replaces `Rollout(batch, noise_source=...)`, `RolloutStep.noise` is replaced by `noise_version`, and `predict`/`encode` no longer take a noise sample. The preprocessor's `noise_source`, `update_internal_state`, `get_internal_state`, `set_internal_state`, `set_rng`, `get_base_seed` and `get_internal_rng` are removed, and `NoiseState` moved to `makani.models.noise_controller`. Checkpoints and results are unchanged.
- A stochastic model refuses a `Rollout` that does not drive its own noise, and a step handed out by a rollout of another model. Noise versions come from one counter shared by all controllers.
- `NoiseController.set_rng` and `ModelWrapper.set_rng` take keyword arguments only (`seed=`, `reset=`), and the input noise is named `"input_noise"` in the controller. `noise_seed_reflect` is now `makani.models.noise.noise_base_seed`, and `run_eager` lives in `makani.models.noise`.
- `make_batch` takes the dynamic features as dicts, `inp_dynamic_features` and `tar_dynamic_features`, instead of `inp_zenith` and `tar_zenith`. `Preprocessor2D.flatten_history` and `expand_history` are now the functions `makani.utils.functions.flatten_history` and `expand_history`, which work on any grid and refuse a tensor of the wrong rank instead of passing it through.
- Networks can take a structured `ModelInput` (`takes_model_input = True`); flat networks are fed by a `FlatInputAdapter` as before. The model owns its noise (`InputNoise`), the wrapper only steers it; `multistep_checkpoint` redraws the noise of each step in its recompute. Checkpoint format 3: input-noise keys move to `input_adapter.input_noise.process.*`, older checkpoints are upgraded. Numerics change slightly, as appended channels are normalized separately and perturbing noise is added after the normalization.
- `IsotropicGaussianRandomFieldS2` and `DiffusionNoiseS2` are isotropic: the orders `m > 0` are drawn with `1/sqrt(2)` of the amplitude, as in torch-harmonics, and the diffusion spectrum is normalized including `l = 0`. The variance is now `sigma^2` at every latitude and for every `kT`; before, it dropped to about half towards the poles and grew with `kT`. Samples for a given seed change. The FourCastNet 3 configs set `lmax: 721` for the input noise, the degrees it was trained with: from torch-harmonics 0.9 on, the default truncates the 721 x 1440 grid to 361.
- The benchmark is a package, `makani.benchmark`: the script is `makani/benchmark/run.py` and still runs as `python -m makani.benchmark`, its helpers, formerly `makani.utils.benchmark`, are `makani.benchmark.helpers`, and `StepTimer`, which every run uses, is `makani.utils.profiling.StepTimer`. `makani.utils.metrics.functions`, which holds the metric classes, is `makani.utils.metrics.geometric_metrics`, apart from `makani.utils.functions`. The file reader `makani.utils.auxiliary_fields.get_bias_correction(path, output_channels)` is `read_bias_correction(path)`; `makani.models.preprocessor_helpers.get_bias_correction(params)` keeps its name.
- `makani.mpu` is split in two. The communication, `mappings`, `helpers`, `halo` and `config`, is `makani.distributed`; the distributed layers are `makani.models.common.distributed`, with `mpu.layers` split into `matmul` (`DistributedMatmul`), `mlp` (`DistributedEncoderDecoder`, `DistributedMLP`, `StochasticMLP`), `patch` (`DistributedPatchEmbed`) and `attention` (`MultiHeadAttention`), next to `layer_norm` and `fft`. `makani.models.common.layers` is split the same way, into `regularization` (`DropPath`, `SeededDropout2d`, `LayerScale`), `patch` (`PatchEmbed2D/3D`, `PatchRecovery2D/3D`), `mlp` (`EncoderDecoder`, `MLP`) and `resample` (`UpSample2D/3D`, `DownSample2D/3D`); `makani.models.common` exports the same names as before. Checkpoints are unaffected: they hold state dicts, not class paths.
- Dependencies point from the models to the communication, not back: the communicator `makani.utils.comm` is `makani.distributed.comm`, and `count_parameters` moves from `makani.models.helpers` to `makani.distributed.helpers`, so `makani.distributed` no longer imports from `makani.utils` or `makani.models`. `BandLimitMask` moves from `makani.utils.grids` to `makani.models.common.bandlimit` (also exported by `makani.models.common`), the MLP state-dict upgrades `flatten_biases` and `upgrade_mlp_state_dict` from `makani.utils.checkpoint_helpers` to `makani.models.common.mlp`, and the normalization kernels from the distributed `layer_norm` to the serial one.
- Module names: `makani.utils.YParams` is `makani.utils.params` (`YParams` and `ParamsBase` keep their names; checkpoints that pickled them under the old module still load), and `makani.utils.parse_dataset_metada` is `makani.utils.parse_dataset_metadata`. FCN3, FCN3.1 and SNO pick their normalization layer with one `makani.models.common.norm_layers.get_norm_layer_handle` instead of three copies.
- Restructured package layout: losses, metrics, data, training and inference are top-level packages (`makani.losses`, `makani.metrics`, `makani.data`, `makani.driver`, `makani.training`, `makani.inference`) instead of living in `makani.utils`; see the package structure in the README for details. `python -m makani.inference` runs as before. `makani` itself exports only `__version__`: the trainers are imported from `makani.training`, the `Inferencer` from `makani.inference`.
- The data processing scripts are the package `makani.datasets` instead of the top-level folder `data_process`: they run as `python -m makani.datasets.<script>` (e.g. `python -m makani.datasets.compute_stats`), install with makani, and their dependencies are the extra `makani[datasets]` instead of `makani[data_process]`. `data_process_helpers` is `makani.datasets.helpers`. The deprecated Copernicus CDS downloader `datasets/copernicus/get_data.py` is removed, with the `legacy_data_process` extra and the `cdsapi` install in the Dockerfiles; `makani.datasets.convert_era5_to_makani_input` with the `wb2` or `ncar` source replaces it.
- MPI is optional for the dataset scripts: they run serially with plain `python` and any h5py, and in parallel under `mpirun`, where mpi4py comes with the new extra `makani[datasets-mpi]` instead of `makani[datasets]`. Parallel HDF5 is only used, and only needed, to write a shared file from more than one rank. The parallel reductions of `get_stats`, `get_spectra` and `get_hydrostatic_balance_climatology` clamp `--reduction_group_size` to a divisor of the number of ranks, so that they run on fewer than 8 ranks with the default, and on machines without GPUs. They refuse a launch of several processes that MPI does not connect, instead of running it as that many copies of rank 0; `makani.distributed.launch.detect_launch` reads what started a process from the environment, Open MPI, then a Slurm step, then PMI, then `WORLD_SIZE`/`RANK`/`LOCAL_RANK`.
- The dataset scripts that compute something are named for it: `get_stats`, `get_histograms`, `get_spectra` and `get_hydrostatic_balance_climatology` are `compute_stats`, `compute_histograms`, `compute_spectra` and `compute_hydrostatic_balance_climatology`, e.g. `python -m makani.datasets.compute_stats`, and so are their main functions (`get_power_spectra` is `compute_power_spectra`). Further dataset scripts are renamed for what they do: `convert_era5_to_makani_input` is `convert_era5`, `convert_era5_invariants_to_makani_input` is `convert_era5_invariants`, `merge_wb2_dataset` is `merge_channels`, as it copies channels between any two makani datasets, and `h5_convert` is `rechunk_dataset`, with its function `rechunk`. `makani.data.data_helpers.get_hydrostatic_balance_climatology`, which loads the climatology for training, keeps its name.
- Retired: the first version of the solar zenith angle, so `makani.third_party.climt.zenith_angle` is now the vectorized one that was `zenith_angle_v2`, with the same results; the Pangu-Weather ONNX model (`pangu_onnx.py`, `onnx_wrapper.py`, the `base_onnx` config and the `onnxruntime` install in the Dockerfiles); and the inference option `--dataset_file_suffix`, ignored since 0.3.
- Quadrature follows the grid: losses, metrics, the preprocessor, the spherical norm layers and the statistics scripts weight a field with the quadrature weights of its grid, those of torch-harmonics (`GridQuadrature(make_grid(img_shape, grid_type))`). On equiangular grids that is Clenshaw-Curtis instead of makani's `naive` rule, which changes loss and metric values on equiangular data by up to about 0.04% relative at 0.25 degrees, and normalization statistics computed anew by a similar amount; Legendre-Gauss grids are unchanged, and so are trained models whose norm layers weight on them, such as FourCastNet 3. The quadrature rules `naive`, `clenshaw-curtiss`, `weatherbench2` and `uniform` and `grid_to_quadrature_rule` are removed, and so are the WeatherBench2-compatible scoring (`--wb2_compatible`) and the `--quadrature_rule` option of the statistics scripts, which take the grid of the dataset's metadata. Grid types are the regular grids of torch-harmonics (`equiangular`, `legendre-gauss`, `lobatto`, `fejer1`, `trapezoidal`) and `euclidean` for the plane; others, such as HEALPix, are refused. Datasets declaring `clenshaw-curtiss` or `weatherbench2` are read as `equiangular`, with a warning.
- The spherical models build their grids once, `make_grid(inp_shape, model_grid_type)` for the input and the output and `sht_grid((h, w), sht_grid_type)` for the processor, and hand the grid descriptors to their layers. The model constructors and configurations keep `inp_shape`, `model_grid_type` and `sht_grid_type`, as PhysicsNeMo stores constructor arguments in its checkpoints. Their layers take grids instead of shapes and grid type names: `RealFFT1`, `RealFFT2` and their inverse and distributed versions take `grid` instead of `nlat`/`nlon`; `BandLimitMask(grid, lmax, type)`; `GeometricInstanceNormS2` and `DistributedGeometricInstanceNormS2` take `(grid, num_features, crop_shape=None, crop_offset=(0, 0), ...)`; `get_norm_layer_handle(grid, embed_dim, normalization_layer)`; `LearnablePositionEmbedding(grid, num_chans, embed_type)`; and the encoders and decoders of FCN3, FCN3.1 and SNO take `inp_grid` and `out_grid`. `ZonalSpectrumAverageBuffer` takes a `grid_type`, as `SpectrumAverageBuffer` does. `compute_spherical_bandlimit(img_shape, grid_type)` is `spherical_bandlimit(grid)`, with the same values on equiangular and Legendre-Gauss grids, so trained models keep their shapes. With it, and with `GridConverter` moving data onto any regular grid of torch-harmonics instead of only Legendre-Gauss, the models run on the Lobatto, Fejer and trapezoidal grids too. `GridConverter` refuses a model grid with latitudes beyond those of the data, as interpolating there would extrapolate.
- Losses, metrics and noise take the grid of their field: every loss and metric, the noise processes (`BaseNoiseS2` and its subclasses, `build_noise`), `InputNoise`, and the spectrum buffers of inference (`SpectrumAverageBuffer`, `ZonalSpectrumAverageBuffer`) take `grid` in place of `img_shape` and `grid_type`. The loss and metric handlers, `InputNoise.from_params`, the stochastic interpolant and the inferencer build it once from the parameters, so configurations are unchanged; the losses, metrics and noise draws are bit-identical to before. Code that builds them directly passes `grid=make_grid(img_shape, grid_type)` (or `sht_grid` for the spectral ones) from `makani.utils.grids`.
- Retired: Earth2MIP support, as Earth2MIP is no longer developed and Earth2Studio, which loads model packages with `load_model_package`, replaces it: `load_time_loop` is removed, model packages no longer contain the Earth2MIP `metadata.json`, and `makani.models.model_package` is gone. The model package is `makani.driver.model_package`.
- `--jit_mode` decides what makani compiles, and by default compiles nothing: `none`, the default, runs everything eagerly; `metrics` compiles the loss terms and the metrics; `all` compiles the model step of training too, as `inductor` did. Before, the loss and metric handlers compiled always, whatever the mode, so a run with the default now runs its losses and metrics eagerly; `--jit_mode=metrics` gives the earlier behavior. `inductor` is still accepted, with a warning, and means `all`. `LossHandler` and `MetricsHandler` take `compile=None`, which follows `jit_mode`, and an explicit `True` or `False` still overrides it. New `makani.utils.jit` with `compiles_model(params)` and `compiles_metrics(params)`.

- Inference can read through DALI: `makani.inference --dataloader dali` (default `multifiles`), or `multifiles: False` in the parameters. The new `DaliInferenceLoader` reads the batches of the rollout schedule through the multifiles dataset in DALI's worker processes, so the batches are bit for bit those of the multifiles loader; it needs `num_data_workers >= 1`. The inferencer no longer forces `multifiles` and only defaults it, to the multifiles loader for real data and to the synthetic loader with `enable_synthetic_data`. New `MultifilesDataset.read_window`, which returns a sample as numpy arrays.
- The DALI loader takes the order, the names and the layouts of its outputs from one list, `SampleSource.outputs()`, and passes on any dynamic feature it names. New `batch_nbytes` and `without_target` helpers; the trainers and the inferencer move batches with `non_blocking=True`, and the autoencoder trainer no longer moves the targets it does not use.
- `Rollout` folds the ensemble into the dynamic features and timestamps of a target step once.
- `compute_stats --wind_stats {componentwise,magnitude,vector}` picks how the paired wind components are normalized. `magnitude` is the former `--wind_angle_aware`, which still works; the new `vector` treats each u/v pair as a tangent vector field, with zero mean and one shared scale `sqrt(E[u^2 + v^2] / 2)` for both components, also for the tendencies.

**Models**
- `SpectralPositionEmbedding` (`makani.models.common.pos_embedding`) is a learnable position embedding of spherical harmonic coefficients: the inverse SHT of learned coefficients of the degrees `l < lmax` and orders `m < mmax`, by default `lmax=32` and `mmax=1`, which depends on the latitude alone. Unlike one free vector per latitude ring, it is band-limited and so smooth up to the poles, whose rings get the least gradient. The coefficients are zero-initialized, so that a network starts as without the embedding, replicated over the ranks, each spatial rank transforming its block of them, and declared not to be weight decayed. A grid that does not resolve `lmax` degrees is refused.
- FP8 precision modes compute the models in FP8: `--amp_mode=bf16-fp8_delayed` (or `bf16-fp8_current`, `bf16-mxfp8`, ...) builds the 1x1 convolutions of the blocks, `PointwiseConv2d` and the nchw `DistributedMatmul`, with FP8 GEMMs of transformer_engine. Before, no network built a transformer_engine layer, so these modes trained in bf16. The layers run the three GEMMs of transformer_engine on the NCHW layout, without permuting to channels-last (`makani.models.common.pointwise_conv_te`), and support delayed scaling, current scaling and MXFP8; under delayed scaling they match `te.Linear` on the same data, outputs, input gradients and amax histories and scales alike. Parameters, their initialization and sharing are unchanged: a parameter-free transformer_engine module per layer holds the FP8 scaling state, `fp8_gemm._extra_state` in the state dict, and checkpoints load across FP8 and non-FP8 modes. The delayed-scaling state, scales and amax histories, is stored as plain tensors, not as transformer_engine's pickle, which it refuses to load by default, and so a run resumes with it. Delayed scaling reduces the amaxes over all ranks, transformer_engine's default, instead of the data-parallel group: the scaling state is that of the serial run over the global batch and the same on every rank, where before each spatial and matmul rank had scales of its own part. Flexible checkpoints store the extra states of the modules per model rank (`gather_extra_states`, `scatter_extra_states` in `makani.driver.checkpoint`); before, they kept only the parameters. A run with another decomposition of the model starts the states afresh, with a warning. Converting legacy checkpoints of several ranks drops the extra states, and averaging checkpoints keeps those of the first. The FP8 layers save their quantized inputs with `save_for_backward`, so that activation checkpointing frees them after the forward. The encoders and decoders stay in bf16, in a `te.autocast(enabled=False)` nested in the FP8 context (`makani.utils.precision.fp8_disabled`), and so do layers whose channels are not divisible by 16 (32 under MXFP8). The grid is padded with zero columns to that multiple, which changes no result, so that all ranks of an unevenly split grid run the same layers in FP8, as the amax reduction over all ranks needs; the layers warn when the padding exceeds 5% of the local grid. Activation checkpointing in FP8 uses transformer_engine's checkpoint (`makani.models.common.activation_checkpoint`), which recomputes in FP8 with the scales of the forward; a checkpoint nested in a checkpointed region runs directly, as transformer_engine's would quantize the recompute with other scales. Compiled models break their graph at the FP8 layers. `AutocastManager` opens `te.autocast` instead of the deprecated `te.fp8_autocast` where it exists. Tests in `tests/test_fp8.py` are skipped without transformer_engine or FP8 hardware. The `use_te` option of `MLP`, `DistributedMLP`, `DistributedEncoderDecoder`, `DistributedMatmul` and the distributed `MultiHeadAttention` is removed: no network set it, and its `te.Linear` permuted the activations to channels-last and back around each GEMM.
- The benchmark records the precision of a run: its FP8 recipe, how many of its pointwise layers ran in FP8 and how many have an FP8 engine, and the transformer_engine version. `scripts/benchmark/sweep.py --amp-mode` takes several modes, one run per mode and decomposition, and `scripts/benchmark/report.py --across-precision` tabulates runs that differ only in their amp mode together, with the speedup of each over the run of its decomposition in `--reference-amp`, bf16 by default.
- Networks can own noise processes, e.g. in latent space, listed through `noise_processes()`; rollouts drive them like the input noise.
- The models compute their 1x1 convolutions as matmuls, with `PointwiseConv2d` and `pointwise_conv2d` of `makani.models.common.pointwise_conv`: the MLPs, encoders and decoders, the skips and residual transforms of SFNO, FCN3, FCN3.1, SNO and AFNOv2, the tensor-parallel `DistributedMatmul`, `StochasticMLP`, the hydrostatic constraint and parametrization, and the random-slice loss; `LayerScale` multiplies instead of convolving. Under `torch.compile`, a convolution made inductor switch the graph to channels-last, and every compiled region receiving the input gradient copied it back, one transposing copy of a feature map per spectral filter and block; the compiled steps of SFNO, FCN3, FCN3.1 and SNO now contain no convolution at all. The layer is as fast as conv2d eager and faster compiled (a 384 -> 73 decoder at B = 4 on 360 x 720: 40 vs 140 ms), and computes its weight gradient in fp32 as conv2d does. Parameters and checkpoints are unchanged; results agree with before to rounding, except that fp32 inference without TF32 now computes these layers in full fp32, as PyTorch does not enable TF32 for matmuls by default while it does for convolutions.
- The instance norms `DistributedInstanceNorm2d`, `DistributedGeometricInstanceNormS2` and `GeometricInstanceNormS2` share one autograd function with an analytic backward, `makani.models.common.layer_norm.instance_norm`. It keeps only the input in its own dtype and two `(B, C)` fp32 tensors for the backward, where the layers kept two fp32 copies of the input, so under bf16 autocast a norm on 256 channels at 721 x 1440 held 1.5 (plain) to 2.5 GiB (spherical) on top of its output until the backward, and now holds nothing beyond the input. The casts to fp32 and back happen inside fused kernels. Under spatial parallelism the backward does one allreduce of a `[2, B, C]` tensor, and the Welford reduction gathers the statistics and the count of each rank in one buffer and combines them in one vectorized step (Chan et al.) instead of a loop over the ranks. Results agree with before to fp32 rounding. `GeometricInstanceNormS2` now divides by the sum of its quadrature weights, as the distributed version does, which changes its statistics on crops, whose weights do not sum to one.
- The real FFT layers (`RealFFT1/2/3`, their inverses and distributed versions) and AFNO transform with `makani.models.common.fft.rfft` and `irfft`. `rfft` is `torch.fft.rfft` with the mode truncation built in and a backward that keeps only the length of the input: the backward of `torch.fft.rfft` keeps the whole input (it reads one size of it, and autograd saves the tensor for that) and returns a stride-2 view that a compiled consumer of the gradient copies, and the backward of the truncating slice zero-filled and copied the full spectrum. The gradient is now a c2r inverse of half the size, contiguous along the transformed dimension. `irfft` zeroes the imaginary parts of DC and Nyquist as `torch_harmonics.fft.irfft` does, but on the device: that one sets them from Python, a host-to-device copy and stream synchronization per call. The 2D and 3D transforms apply the real transform first and truncate before the complex ones. Results agree with before to floating point rounding. `rfft` works under `torch.func` (`grad`, `vmap`, `jacrev`): its autograd function defines `setup_context` and generates its vmap rule.
- The stochastic interpolant is brought up to speed with the rest of the codebase: a `StepWrapper` driven by rollouts and the noise controller, configured by a `stochastic_interpolant` block. Breaking: earlier interpolant checkpoints do not load, and `n_future > 0` is refused.
- `input_soft_clip` softly clips outliers of the model input, e.g. single grid points of ERA5 specific humidity tens of standard deviations off, which blew up forecasts (`makani.models.constraints.SoftClip`). It clips the channels in `names_to_clip` to a `threshold` (8 by default, in the units of the normalized data, also per channel) with `x (1 + (x/s)^p)^(-1/p)` of an even `order` p (8 by default), which leaves the bulk alone: a value of 3 changes by 0.2% at s = 5, where `s tanh(x/s)` would shrink it by 10%. Wind vectors are clipped by their magnitude, with one threshold for both components, which keeps their direction; a wind component without its partner is refused, and a warning is issued when the statistics of the wind are not those of `wind_stats="vector"`. The clip acts on every step of a rollout, before the history normalization, and on the start of the path of a stochastic interpolant.

**Metrics**
- A kinetic energy ratio, `GeometricKineticEnergyRatio`, reports for each wind pair the kinetic energy of the forecast over that of the observation in bands of spherical harmonic degree: the energy of a degree comes from the vector SHT of the pair, `l (l + 1) / 2` times the power of its velocity potential and streamfunction, so that the bands sum to the mean of `|u|^2 / 2` over the sphere, in physical units. A ratio below 1 is a smoother forecast, above 1 one with more energy at those scales than the observation, such as a mode that grows in the rollout. Like the SSR, the ratio is computed per sample, averaged over the members and then over the samples. With missing values, a pair counts for a sample only if both of its components are valid everywhere; a field with holes, or a pair whose v component is missing, is left out. The `MetricsHandler` computes it for the pairs named by their u component in `ke_ratio_var_names` of the configuration (e.g. `["u10m", "u500"]`, off by default, since it holds the Legendre tables of a vector SHT), in the bands `ke_ratio_bands`, by default `l < 60`, `60 <= l < 360` and `360 <= l` up to what the grid resolves (720 on the 721 x 1440 grid), and logs `KE ratio uv500[60,360)(24)` and the like. `MetricRollout` takes the channels a metric reads, `input_channels`, apart from those it reports, and labels for an extra dimension of the metric, `aux_labels`, which it reports as metrics of their own.

**Fixed**
- The rollout buffers of inference under matmul parallelism: the ranks of a matmul group, which hold the same shard of the output, all wrote it, the same values to the same place of the file, and for `RolloutBuffer` that multiplied the I/O of the fields by the size of the matmul group. Only the first rank of a matmul group writes now, in `RolloutBuffer` (buffered and streaming), `TemporalAverageBuffer`, `SpectrumAverageBuffer` and `ZonalSpectrumAverageBuffer`; the files are the same as before.
- A run with model parallelism and `save_checkpoint: flexible` could hang after the checkpoint of the first epoch whose validation loss did not improve. Each rank decided whether to save the best checkpoint by looking for the file of its own model rank, but a flexible checkpoint is written as the file of model rank 0 only, so the other model ranks never found one and saved every epoch, while the ranks of model rank 0 saved only when the loss improved; saving takes collectives over the model ranks, and the ranks waited in different ones until the collective timeout. The trainers now decide with `makani.training.training_helpers.save_as_best_checkpoint`, which checks for the file of model rank 0 on world rank 0 and broadcasts the decision.
- The history normalization (`HistoryNormalization.compute_stats`) gave wrong gradients under spatial parallelism wherever the gradient flows through its statistics, as when the window holds predictions in multistep training: the standard deviation was computed about the mean before the mean was copied to the parallel region, so the gradient of the mean through the standard deviation was each rank's partial sum. The mean is now copied right after its reduction. In the `timediff` mode, the per-sample mean of the time differences broadcast against the longitudes when the variance was computed, which failed for any batch size but 1 and the number of longitudes; it is now broadcast over the sample.
- With a history window (`n_history > 0`), the big skip of FCN3.1 and SNO added the oldest state of the window instead of the latest: the window is stacked oldest first, and they took the predicted channels at the start of the input. A rollout then advanced as x(n + 1) = x(n - 1) + F(x(n - 1), x(n)), a two-level scheme whose computational mode, an error that alternates in sign from step to step, one-step training does not constrain, so that rollouts can blow up while the one-step error keeps improving. They now add the latest state; SNO takes `n_history` and `aux_channel_names` to locate it. With a history window, FCN3.1 also read the land-sea mask for its SST imputation from a channel of the first step instead of the static channels, and, from `n_history = 2`, passed wrong dynamic auxiliary channels to its auxiliary encoder. Checkpoints trained with a history window learned around the old anchor. FCN3 refuses a history window, and SFNO's big skip is a learned map of the whole input, so they are not affected.
- `DistributedMatmul` adds its bias in the dtype of the product, as `conv2d` and `linear` do under autocast and as the serial layers do. The fp32 bias promoted the output and the activations after it to fp32 under bf16 autocast, so that a distributed model computed in another precision than the serial one, and its FP8 layers quantized other values.
- The spectral coherences of `SpectralAMSELoss` (`amse`), `CoherenceRegularization` and `SpectralCoherenceLoss` divided by `sqrt(P_x * P_y + eps)`, a fixed eps added to the product of the powers of a degree. Where the powers are small, as at the small scales of a red spectrum, the eps swamped them and pulled the coherence of a perfect forecast towards 0: AMSE scored about twice the power of the small scales instead of 0, with a gradient that damped them, and `CoherenceRegularization` scored 0.086 instead of 0 on unit noise at 32 x 64. They now divide by the product of the norms, each clamped to the smallest positive number of its dtype (`makani.losses.base_loss.norm_product`), so a perfect forecast scores 0 at any scale, and a degree without power gives a coherence of 0 and finite gradients, where AMSE gave NaN gradients. The `eps` argument of `amse` and `CoherenceRegularization` is gone.
- The `MetricsHandler` logged the L1 metric in normalized units, since it did not pass the channel scales to the L1 rollout as it does for RMSE, CRPS and the spread. L1 is now in the units of the data, like the other dimensional metrics; L1 values of earlier runs are in normalized units.
- The `MetricsHandler` logged NaN for the spread and SSR of a single-member forecast, as in deterministic inference, since both divide by E - 1. It now computes them only when `ensemble_size > 1`.
- The probability weighted moment CRPS (`crps_type: "probability weighted moment"`) ignored `ensemble_weights`. It now weights each member by w_i / W in the skill and each pair of members i != j by w_i w_j / (W^2 - sum_i w_i^2) in the spread, which is the fair CRPS of the weighted ensemble and the unweighted estimator for equal weights.
- The spectral losses weight the spectral coefficients (l, m), as `SpectralLpLoss`, `SpectralH1Loss` and `amse` do, but the Sobolev, spectral L2 and corrected spectral L2 energy scores and `SpectralCoherenceLoss` dropped their weights, and `SpectralCRPSLoss` failed on weights with batch or channel dimensions. All of them now multiply their weights onto the `lm_weights` and raise a `ValueError` for weights whose last two dimensions are not the local (l, m) domain, such as weights on the grid. `GradientCRPSLoss` with `absolute=False` failed on spatial weights with channels, it now gives both components of a channel's gradient the channel's weights.
- The `LossHandler` could not build the hydrostatic balance loss (`hydrostatic`): its `compute_channel_weighting` did not take the `time_diff_scale` of the handler, and in multistep training it multiplied the stacked lead steps with the matrix of one step. It now gives the layer residuals of each lead step, refuses `temp_diff_normalization`, and refuses weights per channel, since its residuals combine channels.
- The `LossHandler` failed with an `IndexError` on `channel_weights` given as a flat list, and with temporal-difference normalization it scaled the list before checking its length. It now takes a flat or a nested list with one weight per channel of the loss, and raises a `ValueError` for a list of the wrong length.
- The log of a resumed or warm-started run printed the path template of its checkpoint, with `{mp_rank}` in it. It now names the files the restore reads: the file of model rank 0 in flexible mode, and the first to the last file of the model ranks in legacy mode.
- `SpectralRegularization` with `logarithmic=True` took the logarithm of the power spectra without its `eps`, so a degree without power gave -inf and a NaN loss. It now compares log(psd + eps).
- The running stats of the `LossHandler` started the sum of squared deviations of Welford's algorithm, `running_var`, at 1 instead of 0, and `reset_running_stats` reset it to 1. The variance was therefore too large by 1/n, n the number of samples, 0.01 when uncertainty weighting starts after 100 samples, which outweighs the variance of typical normalized losses. It now starts at 0, `get_running_stats` returns 0 before there are more samples than the correction, and uncertainty weighting floors the variance at the handler's `eps`, so that a loss that does not vary gets a bounded weight. The extra 1 in checkpoints of earlier runs decays like 1/n after resuming.
- Losses that reduce over their channels (`channel_reduction`, the default of the energy scores, and `gaussian_mmd` with it) in multistep training (`n_future > 0`): they summed over the channels of all lead steps at once and gave one value for the whole trajectory, which raised a shape mismatch in the `LossHandler` next to any other loss, and alone was counted once per step. They now reduce over the channels of each step (`makani.losses.base_loss.sum_channels_per_step`) and give one value per step, the value of the step on its own. The spread tempering of the energy score (`spread_temper_steps = T`) scaled the spread of the whole trajectory by the factor of each step, and that factor was `max(k / T, 1)`, more than the full spread after step `T`, where the score is improper. It now scales the spread of each step `k` by `min(k / T, 1)`: the skill alone at the first step, then the spread ramps up to its full weight at step `T`.
- The spectral losses `ensemble_spectral_crps` (`SpectralCRPSLoss`), `SpectralL2EnergyScoreLoss` and `CorrectedSpectralL2EnergyScoreLoss` scaled the SHT coefficients by `1 / sqrt(4 pi)` on top of their `lm_weights`, which already hold the `1 / (4 pi)` of the mean over the sphere, so they came out `sqrt(4 pi)` (CRPS, energy scores with `beta = 1`) or `4 pi` (`beta = 2`) too small. Now a spectral L2 energy score is, by Parseval, the grid L2 energy score of a band-limited field. The spectral CRPS of FourCastNet 3 (`relative_weight: 0.1`) weighs about 3.5 times more against the grid CRPS than before. `SobolevEnergyScoreLoss` and `SpectralCoherenceLoss` build their own weights without the `1 / (4 pi)` and were right.
- `GaussianMMDLoss` (`gaussian_mmd`) is the squared MMD between the ensemble and the observation, `1 + E k(X, X') - 2 E k(X, y)`, with the Gaussian kernel `exp(-d^2 / (2 sigma^2))` of the `L^beta` distance over the grid. It returned `E k(X, y) - E k(X, X') / 2`, the form of the CRPS, where both terms are distances, not kernels, so minimizing it drove the members away from the observation; its kernel took `exp(-d^4 / (2 sigma))` for the default `beta = 2`. A perfect forecast now scores 0. `alpha` blends the fair estimate of `E k(X, X')` with the average over all pairs, including each member with itself; a single member uses the latter. `channel_reduction` sums over the channels, where it summed over the batch, and without it the loss weights its channels like the other losses, so it runs in the `LossHandler` next to other losses and with `n_future > 0`, where it raised a shape mismatch. Its scores are not comparable with earlier runs.
- Dataset statistics of a single combined file (`.h5v`) on several ranks: `compute_stats`, `compute_spectra` and `compute_hydrostatic_balance_climatology` read each rank's samples up to and including the first sample of the next rank, so the samples at the rank boundaries counted twice. The four statistics scripts now share the split into per-file ranges, `makani.datasets.helpers.file_sample_ranges`.
- `compute_spectra` transformed every dataset on an equiangular grid; it now uses the `grid_type` of the dataset metadata, as the other statistics scripts do.
- `compute_histograms` failed for more than one batch per file, as the quadrature weights grew with every batch, and for `nbins <= 0`, whose fallback of `sqrt(count)` bins was not an integer.
- The ACC AUC of validation and inference is the mean of the ACC over the rollout, from the first to the last step. It integrated the N steps with a width of 1/N instead of 1/(N - 1), so it came out at (N - 1)/N of the mean, e.g. 0.75 for a perfect forecast over 4 steps, and 0 for a rollout of a single step, which now reports its ACC. Reported ACC AUCs are larger than before, by N/(N - 1).
- `normalize_static_features: True` raised an `AttributeError` for every configuration, as the area-weighted normalization read `params.img_shape`, which nothing sets; with a crop, it also applied the weights of the crop to the whole grid. It now takes the statistics over the crop, the region the model sees.
- `GaussianMMDLoss` with spatial weights and without `ensemble_distributed`, in a run with ensemble parallelism: the weights were split over the ensemble ranks anyway, so the loss raised a shape mismatch.
- `DropPath()`, whose default rate `None` is documented as disabled, raised a `TypeError` in training mode.
- `SpectralH1Loss` under spatial parallelism with more than one rank in `h`: the weights were not reduced to the local chunk of the rank, so building the loss raised an `AttributeError`.
- `LossHandler` with several losses and `n_future > 0`: the channel weights were tiled as `[loss 0, loss 1] * steps` and the multistep weights were repeated across all losses, while the losses are laid out as `loss 0: steps, loss 1: steps`. Each loss therefore got weights of the wrong loss and lead time, silently. With a single loss, nothing changes. `uncertainty_weighting` and `balanced_weighting` with `n_future > 0` crashed on the same mismatch, and now run.
- Learnable white noise (`IsotropicGaussianRandomFieldS2`) under spatial model parallelism: its `sigma_l` is sharded over `h` and `w` but was not annotated as shared over `matmul` only, so the gradient reduction summed the shards of other ranks (or failed on shards of different sizes) and `sync_params` overwrote them with those of rank 0.
- Noise under matmul parallelism: `noise_base_seed` seeded by the model rank, so the matmul ranks, which hold the same input, drew different noise. It now seeds by the spatial rank; without matmul parallelism the seeds are unchanged.
- `NoiseController.set_rng` (and `ModelWrapper.set_rng`) seeded every rank alike, so after it the spatial shards drew the same coefficients and the data-parallel and ensemble ranks the same noise. A process now lays the seed out over the ranks as it was built, through `rank_seed`, keeping centered pairs; serially the seeds are unchanged. Noise processes take a `centered` flag, which `build_noise` passes on.
- A resumed training run replayed the noise of the start of the run, since the noise generators were not checkpointed. The checkpoint now stores the generators of all ranks (`noise_rng_state`), and resuming restores them; a checkpoint without them, or one of another decomposition, resumes with fresh streams and a warning. New `NoiseController.get_rng_state` and `set_rng_state`.
- Checkpoints carry a format tag, `checkpoint_format`, with the mode they were written in, legacy or flexible, and a format version (now 1). A restore in the other mode is refused with a message naming the mode to use when the tensors would not match, i.e. with model parallelism on either side, and a checkpoint of a newer version is refused under `strict_restore`. Checkpoints without the tag still restore, with a warning.
- Checkpoints of matmul-split models: the layers that are split over the `matmul` group have the same parameters as their serial counterparts, so a flexible checkpoint restores across any decomposition. `MLP` keeps its layers as `fc1` and `fc2`, as `DistributedMLP` does, rather than in a sequence (`fwd.0`, `fwd.3`); `DistributedMatmul` keeps a 1-D bias in the nchw format, as `nn.Conv2d` does, rather than `(1, C, 1, 1)`; and `DistributedEncoderDecoder` counts `num_layers` as `EncoderDecoder` does, the hidden layers before the output layer. Before, the latter built one layer less than the serial network and refused the default of one hidden layer under matmul parallelism. The checkpoint format version is now 2: checkpoints of an earlier version, or without a format tag, are upgraded on restore, model state and optimizer state alike (`upgrade_checkpoint`), including by the checkpoint converter; those of matmul-split SFNOs cannot be, as their encoders and decoders had another structure.
- Gradient reduction under matmul parallelism: a layer that is not split over the `matmul` group computes the same on every matmul rank, so each rank holds its full gradient, but the reduction summed the gradients over the group, doubling them with two matmul ranks, or left them unreduced, so that the replicas could drift apart under reduced precision. The annotation `is_shared_mp` is now a dict from model-parallel group to reduction, e.g. `{"spatial": "sum", "matmul": "avg"}`: summed over ranks that split the computation, averaged over ranks that replicate it. All layers are annotated this way, which also sums the gradients of the q/k norms of `DistributedAttention` over its heads and marks `DistributedPatchEmbed` as split over `matmul`; a parameter without annotation is shared as `DEFAULT_SHARING`, and the list form of earlier versions is still read. `get_sharing` in `makani.distributed.helpers` reads an annotation for `init_gradient_reduction_hooks` and `sync_params`, and refuses a parameter shared over a group it is sharded over. The distributed layer tests reduce their gradients themselves.
- The distributed instance norms (`DistributedInstanceNorm2d`, `DistributedGeometricInstanceNormS2`) stalled the host on every call: their Welford reduction gathered the per-rank statistics without passing the shapes, so the gather first all-gathered the sizes and read them back with one `.item()` per rank, a device-to-host copy that waits for all queued GPU work. That left the GPU idle between the norms of every block. They now pass the shapes, one entry per rank, which removes the synchronization; results are unchanged.
- Attention: `MultiHeadAttention` replaces ViT's `Attention` and `DistributedAttention`, with the heads split over the `matmul` ranks if there are several. It has separate `q`, `k` and `v` projections, each split by heads, so that a checkpoint is the same for any decomposition (the fused `qkv` of `DistributedAttention` was split by contiguous rows, which interleaved the heads by the matmul size), a bias on the output projection in either case (`DistributedAttention` had none), and no biases the softmax removes: none for the keys without `qk_norm`, and none in the normalization of the keys with it. The attention dropout applies in training only. Breaking: ViT checkpoints of earlier versions do not load.

## 0.3.0

**Breaking**
- Python >= 3.11, torch >= 2.12.1, torch-harmonics == 0.9.4 (with the DISCO and zero-width halo fixes; 1.x is not compatible yet), PhysicsNeMo >= 1.3.0 (1.x and 2.x), DALI 2.x (`nvidia-dali-cuda120`), zarr >= 3. Dropped numba, pynvml, progressbar2, jsbeautifier and moviepy; matplotlib is a core dependency, and the `vis` extra installs imageio/imageio-ffmpeg. New `test`, `data_process`, `legacy_data_process` extras.
- Dataloaders emit dict batches (`input`, `target`, `*_dynamic_features`, `*_timestamp`; `(B, T, C, *grid)`). Timestamps are always present, and `return_timestamp` is gone.
- `Rollout` owns the multistep loop, and `StepWrapper` replaces `SingleStepWrapper`/`MultiStepWrapper`. The preprocessor is stateless between steps. `multistep` in `get_model`/`load_model_package` has no effect and warns, and `get_model` no longer accepts other extra arguments. `continue_noise` is replaced by `Rollout(noise_state=...)`.
- DALI dataloader state format 2 (timestamps are pipeline outputs, on the GPU): a dataloader state saved before is refused on resume, or skipped with `strict_restore: False`.
- Old DALI helpers (`data_loader_dali_2d`, `dali_es_helper_*`) were replaced by `dali_dataloader` + `sample_source`. Removed `img_utils`, `factorizations`, `drift_regularization`, `DistributedAFNO2Dv2`, and the fin/fout matmul split, which is now plain fork-join.
- SFNO: no MLP output bias before instance norms (dropped on load); the frequency `pos_embed` has a full `m = 0` column. Old checkpoints of the latter need conversion, and runs from before cannot resume their optimizer state.
- Bias, spectrum and zonal-spectrum files give lead times in hours, and the zonal spectrum's Nyquist bin is half its previous value. An unknown `scheduler` name raises. Pangu checkpoints trained before the shifted-window roll fix do not reproduce exactly.
- The ACC, SSR and spread of data with missing values come out lower: each sample's value is taken over its valid area, and the samples are averaged weighted by that area. They were too large by the inverse of the valid-area fraction (its square root for the spread).
- Invariants are stored in a single file; the model package renamed `land_sea_mask.nc` to `land_mask.nc` and normalizes its file names. Cosine zenith calculation uses an optimized vectorized routine.

**Data**
- Pluggable storage backends: makani HDF5, concatenated HDF5, makani zarr, ARCO/WB2 zarr, and native ICON mesh. Datasets declare and verify their grid. Shared channel mapping and metadata rework.
- Subsampling/resampling, NaN targets with masked losses and imputation, leap-year-safe concatenation, dataloader save/restore, GDS and O_DIRECT IO.
- Conservative remapping (raster and mesh to lat/lon), serial and spatially distributed.
- Converters: WB2 and NSF NCAR ERA5 merged into one tool with pluggable sources, NCAR downloader, h5_convert fixes, improved stats (Welford, power spectra).

**Models**
- Model package rework built on `Rollout`.
- Stochastic MLP with log-std spread, and a reworked noise module that is compilable and has a save/restore state.
- Water-channel constraint handling cleaned up in FCN3 and the constraints wrapper. Fixes to Pangu's shifted-window roll and `BandLimitMask`'s default band limit.

**Training**
- Multistep weighting modes and multistep checkpointing. The ensemble is folded into the batch dimension. Validation streams one lead time at a time. Trainers no longer read a setup batch, so the first DALI epoch is complete.
- Losses: MMD, kernel score, corrected and memory-efficient energy score, and relative losses. Fixes to CRPS gradients, the coherence loss, the energy-score spread at E=1, Gauss CRPS with ensemble weights, and the CRPS losses for single-member forecasts with spatial weights. Losses are AMP-safe.
- `torch.compile` and inductor support (step-level compilation), FP8/TE autocast options, weight-decay param groups, gradient-norm tracking, and an LR warmup start.
- Checkpoints carry a parameter-name checksum. Fixes to the distributed instance norm and to the parallel comm routines, which moved from PhysicsNeMo to TH/makani.

**Inference and tooling**
- Streaming rollout buffer (GDS, O_DIRECT), WB2-compliant output, and an inferencer built on `Rollout`. With `n_history > 0`, the buffer records the latest step of the window, at its time, as the initial condition, not the oldest.
- Metrics: ACC, SSR and spread of masked data are valid-area-weighted averages of the per-sample values; spectrum buffers count the Nyquist order once; climatology and mask lookup work with history and across leap years. `load_time_loop` steps by `dt * dhours` hours.
- Visualization rewrite: op registry instead of eval, rank 0 only, progress bars on videos; GIFs and rollout videos without moviepy, and a rollout plotting script.
- Benchmark tool, profiling/NVTX fixes, pre-commit and a style CI, CI on pull requests, API docs, SECURITY.md, and broad test coverage, including distributed tests with DALI, on CPU and under srun/mpirun. CUDA-only calls are guarded, so runs work on CPU. Docker images build for B300/GB300.
